# Porting notes: package "wx" (wxWidgets, app shell, UI, script debugger, Window area)

## Result

With `-I src/platform/posix/wx` on the command line (see lead requests), every translation
unit of the package compiles, and so does every TU elsewhere that failed only because it
reaches a wx header (sim/CWldSession, sim/SimDriver, sim/Sim, sim/CArmyStats,
render/*, net/CGpgNetInterface, gpg/core/reflection/Reflection, ...). Checked: 76 TUs that
include wx directly or transitively, plus the 3 new platform files. 61 of the 64 files the
census attributed to this package or to wx now compile; the other 3 are WinApp.cpp and
WinMain.cpp (excluded, replaced) and console/CConCommand.cpp, whose remaining error is not wx
(`throw std::exception("...")`, an MSVC-only constructor; owner: console/sim-game).

Remaining non-wx errors seen in other packages' files while checking (not fixed, not mine):
CConCommand.cpp `std::exception(const char*)`; Sim.cpp `sscanf_s`; CLobby.cpp boost 1.34
`std::unary_function`; StartupHelpers.cpp `<dsound.h>` then the d3d10/d3dx10 headers;
render/d3d/CD3DDevice.cpp `AddFontMemResourceEx` (gdi32, see lead requests).

## The wx stand-in (`src/platform/posix/wx`)

wxWidgets 2.4.2 is not part of the POSIX build. `src/platform/posix/wx/wx/` is a
header-only stand-in with the same class names, hierarchy (wxObject > wxEvtHandler >
wxWindowBase > wxWindow > wxTopLevelWindow > wxFrame/wxDialog, wxControl > ..., wxApp >
wxAppBase), signatures, macros and constants as wx 2.4.2 MSW (Unicode, FINAL), limited to
the API the engine uses. Every `wx/<name>.h` the engine includes exists and pulls in the
whole stand-in (`wx/wx.h`); the code is in `wx/faf/{string,object,gdi,event,window,
controls,toplevel,app,files}.h`; `wx/defs.h` has the types, styles, ids and WXK_ codes.

Behaviour (real, because engine code relies on it):

- `wxString`: wide string, wx's conversions (`wxConvUTF8` UTF-8<->UTF-32, `wxConvLibc`
  byte-per-code-point as the "C" locale), `mb_str`, `Printf`/`Format` (MSVC wide-format
  rules - `%s` is a wide string - translated to the POSIX spellings), `ToDouble`/`ToLong`
  (wcstod/wcstol), substrings.
- Event tables (`DECLARE/BEGIN/END_EVENT_TABLE`, all `EVT_*` the engine uses, custom
  entries via `DECLARE_EVENT_TABLE_ENTRY`), `Connect`, handler chains
  (`PushEventHandler`/`PopEventHandler`), `ProcessEvent` with command-event propagation to
  the parent, `AddPendingEvent` (queued, delivered by `wxApp::ProcessIdle`),
  `DEFINE_EVENT_TYPE`/`wxNewEventType`.
- Windows: parent/child ownership (a parent deletes its children), sizers owned by their
  window, menu bars owned by their frame, `Destroy()` of top-level windows deferred to the
  next idle (`wxPendingDelete`), `Close()` with the library's default close handlers,
  geometry and state remembered. Controls keep their contents: text, check state, combo
  items, list rows/states (virtual lists via `OnGetItemText`), tree nodes with
  `wxTreeItemData` ownership and sorting (wxTreeCtrl and the contrib wxTreeListCtrl),
  notebook pages, splitter panes, toolbar tools. Text controls send
  `wxEVT_COMMAND_TEXT_UPDATED` on change, notebooks send page-change events, trees send
  expand/collapse events (as the native controls do).
- `wxApp`: `IMPLEMENT_APP_NO_MAIN`/`DECLARE_APP`/`wxGetApp` as in wx, `wxEntry` (builds the
  app through the initializer, `OnInit`; with `enterLoop=false` returns 1 and leaves the
  app to the caller), `wxApp::CleanUp` deletes it. `Pending()` is false (no native queue);
  `ProcessIdle()` delivers pending events, deletes pending windows, returns false.
- `wxCharCodeMSWToWX`/`wxCharCodeWXToMSW` (wx 2.4.2 msw/window.cpp tables; the Maui key
  codes are WXK_ values, `EMauiKeyCodeTypeInfo.h` confirms the numbering).
- `wxURL`: protocol parse with the library's registered protocols (http, ftp, file).

Headless (faf_replay; with the window system up, see macos/porting/shell.md, the windows are real): nothing is displayed: no native window exists (`GetHandle()` is 0, `MSWWindowProc` answers
like DefWindowProc), showing a top-level window logs once (`FAF_POSIX_STUB`), modal dialogs
return `wxID_CANCEL` without a loop, `wxMessageBox`/`wxMessageDialog` print to stderr and
return the negative answer, bitmaps/images cannot be loaded (LoadFile fails, logged), no size,
move or paint events are generated by geometry changes. A smoke test (event-table dispatch
through a multiply-inherited dialog, pending events, text events, delayed destroy, tree
list, string formatting/UTF-8, key mapping, app create/cleanup) passes.

`platform/WxWidgets.h` has a `FAF_POSIX` branch that includes `<wx/defs.h>` only (no NDEBUG
juggling, no `<windows.h>`/winundef); the Windows code is unchanged under `#else`.

## Excluded and replaced (`macos/exclusions.d/wx.cmake`)

- `moho/app/WinApp.cpp` -> `src/platform/posix/stubs/wx/WinAppPosix.cpp`. Defines everything
  `WinApp.h` exports plus `moho::sLogWindowTarget` and `IMPLEMENT_APP_NO_MAIN(moho::MohoApp)`.
  Real: `WIN_AppExecute` (the Windows loop's order of calls without the keyboard hook / Win9x
  check / COM init), task stages, wake-up timer, current app, main window, crash-report
  attachments, `PLAT_CreateGameLogForReport`, call stacks (`backtrace`/`dladdr`, demangled),
  `WIN_OkBox`/`WIN_YesNoBox` (through MessageBoxW: stderr, IDNO), `WINX_*`.
  Stubs (`FAF_POSIX_STUB`): registry (every key absent, same log lines as the Windows failure
  path), clipboard (empty / false), crash dialog (report to log + stderr), SEH filter, splash
  (the stand-in cannot load the PNG, as when the file is missing).
- `moho/app/WinMain.cpp` -> `src/platform/posix/stubs/wx/WinMainPosix.cpp`, which only
  registers WinMain's console commands (`SC_StartMemoryLog`, `SC_StopMemoryLog`,
  `faf_crashtest`) with their names/descriptions; they log that they are unavailable. The
  headless runner provides `main()`.

Everything else of the package compiles unchanged, including the script debugger windows
(`ScrDebugWindow`, `ScrFileCtrl`, `ScrSourceCtrl`, `ScrWatchCtrl`, `ScrGotoDialog`),
`WEmitterWx`, `WxUrl` (ShellExecuteW is the Misc area's) and `WxRuntimeTypes.cpp`, which also
holds the world renderer (`WRenViewport`) and the log window/target.

## Guarded edits to engine files (owned)

- `moho/app/WxRuntimeTypes.cpp`: `<d3d9.h>` and `gpg/gal/backends/d3d9/DeviceD3D9.hpp` are
  not included under `FAF_POSIX` (no D3D9 backend on POSIX; nothing in the file uses them).
- `moho/ui/UiRuntimeTypes.cpp` (`StoreEngineFloatStat`): `std::bit_cast<long>(float)` does
  not compile with a 64-bit `long`; under `FAF_POSIX` the float's 32 bits are cast through
  `std::int32_t` (rule 2; the `long` Interlocked overloads are 32-bit, compat/Sync.h). UI
  stat only.

## Window area (`compat/Window.h`, `WinCompatWindow.cpp`)

user32 for a process without windows, in Windows' return conventions: messages (no queue;
`GetMessageW` returns WM_QUIT rather than block forever), windows (none; the desktop window
is a sentinel HWND whose rect is the monitor), menus/dialogs (fail), input (keys up, cursor
position/clip/show-count tracked), hooks (accepted, never called), `SystemParametersInfoW`
and `GetSystemMetrics` (one primary 1920x1080 monitor, accessibility features off, setters
accepted), monitors, clipboard (none), message boxes (stderr; IDOK for OK boxes, the negative
button otherwise), plus the VK_/WM_/SB_/SC_/HT_/SW_/SWP_/SPI_/SM_/MB_/MF_/CF_/WS_/GWL_
constants and MSG/MONITORINFO(EX)W/KBDLLHOOKSTRUCT/ICONINFO/CURSORINFO.
`MsgWaitForMultipleObjects(Ex)` ended up in the Sync area and `ShellExecute(Ex)` in Misc
(both agents got there first); the Window area defers to them.

## Headless runner: entry points

wxTheApp must exist: `SimDriver::PerformNextEvent`, `cfunc_ExitApplication` and the
`/exitongameover` path in `CWldSession` call it unconditionally. Two ways:

1. Derive a headless `moho::IWinApp` and run it with `moho::WIN_AppExecute(&app)` (creates
   the MohoApp via `wxEntry(0, 0, nullptr, 0, false)`, runs the before-events stage, idle,
   `app.Main()`, before-wait stage and the wait-handle/wake-timer wait each turn, ends on
   `wxTheApp->ExitMainLoop()`, e.g. `/exitongameover`, then `Destroy`, `RES_Exit`).
2. Or drive it yourself after `wxEntry(0, 0, nullptr, 0, false)`.

`CScApp::Init` is not headless (REN_Init, UI_Init, CreateDevice/CreateAppFrame, OPTIONS_Apply).
A headless `Init` would do what it does minus those: `moho::APP_InitializeIdentity()`,
`IWinApp::AppInitCommonServices()` (log history, `/log` file, `gpg::REF_RegisterAllTypes`,
resource manager, `DISK_SetupDataAndSearchPaths("SupComDataPath.lua", ...)`),
`moho::USER_LoadPreferences(...)`, `moho::SCR_LuaDoScript(moho::USER_GetLuaState(),
"/lua/userInit.lua", nullptr)`, `moho::USER_EnsureDocumentDirectories()`. The session start
is `CScApp.cpp`'s anonymous `InitializeSessionFromCommandLine` for `/replay`:
`moho::VCR_SetupReplaySession(path, &failureReason)` then
`moho::WLD_BeginSession(sessionInfo)` (replicate it; it is not exported). Per frame the sim
part of `CScApp::Main` is `moho::WLD_Frame(dtSeconds)` (false = quit) and
`moho::sUserStage->UserFrame()`; the rest (SND_Frame, CAM/REN_Frame, ADXM, D3D refresh, UI
frame rate) is presentation. `/framerate N` gives `CScApp::Main` a fixed frame time;
`wld_FrameClock` / `sim_ReplayLead` govern pacing. `CScApp::Destroy` is the teardown order
(WLD_Teardown first).

Implemented in wave 2 by the runner package: `src/platform/posix/runner/` (option 1, a
headless `IWinApp` run through `WIN_AppExecute`); see `macos/porting/runner.md`.

## Open issues

- Static-initialisation order: WinApp.cpp's statics (the log target's registration with gpg
  logging, the wake-up timer bootstrap, the wx app initializer) now run from the stubs
  directory, i.e. after every engine TU instead of at WinApp.cpp's place in sources.cmake.
  The log window's target misses lines logged by earlier static initialisers; nothing else
  depends on them that I could find. If the lead prefers the original position, WinApp.cpp
  could instead be kept in the build with its body under `#if !defined(FAF_POSIX)` and the
  replacement `#include`d in the `#else`.
- `wxCharCodeMSWToWX`/`WXToMSW`: reconstructed from wx 2.4.2 from memory (the library source is
  not available here). The numpad operator keys (VK_MULTIPLY... map to WXK_MULTIPLY... rather
  than WXK_NUMPAD_*) are the uncertain rows. UI key bindings only.
- The Window area's monitor is a fixed 1920x1080 and there is no clipboard; both belong to the
  SDL3 shell (milestone 2).
- GDI (gdi32) has no owner yet: `GetDC`/`ReleaseDC`, `CreateDIBSection`, `BITMAPINFO`,
  `BITMAPV5HEADER`, `HBITMAP` use, `DeleteObject`, `GetObject`, `FillRect`, `GetStockObject`,
  `AddFontMemResourceEx` (render: common/WindowsCursor.cpp, vulkan/GpuDrivenVulkan.cpp,
  d3d/CD3DFont.cpp, d3d/CD3DDevice.cpp).
